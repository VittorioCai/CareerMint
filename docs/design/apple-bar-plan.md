# 做到 Apple 那一档 — 分步计划

现在是 B。视觉语言的问题基本解决了，挡在前面的已经不是「好不好看」，是**信息设计**和**每个状态是否被想过**。

---

## 先定义「Apple 要求」，否则后面全是感觉

不是风格，是六条可以判定失败的约束：

1. **屏幕上没有一样东西是白来的。** 每个元素要么承载信息，要么承载操作。装饰性的编号、空的格子、"未说明"这种占位当内容 —— 一律删。
2. **每个状态都被设计过，不只是 happy path。** 空、一条、很多条、加载中、失败、内容超长 —— 六种，每个界面都要有答案。
3. **无障碍是约束不是清单。** 对比度、焦点、键盘、屏幕阅读器 —— 不达标就是 bug，和功能 bug 同级。
4. **动效解释来去，不做装饰。** 每一段动画要能回答"这东西从哪来、去哪了"。
5. **排版是一套系统，不是一堆数字。** 有级差、有行长、有中英混排的规则，全站只用这套。
6. **不上线死控件。** 现在顶栏的搜索、通知、AI 助手都挂着"即将开放" —— Apple 不会把三个不能用的按钮放在每一屏最显眼的位置。

**验收方式**：每个阶段都有一个能跑、能失败的检验。没有检验的阶段不算做完。

---

## 阶段 0 · 清场（半天）

两个是我改版时制造的，一个是一直都在的。先清掉再往前走。

| 问题 | 修法 |
|---|---|
| 职业档案空态有两个主按钮（「手动添加事实」和「去上传简历」都是奶油 + 硬投影），且上面那个压在卡片边缘 | 合并成一条路径。上传是主，手动写是次级文字入口，都放进空态卡里 |
| 「删除记录」用 `--ink-soft` (#94a09b) 配白底，对比度 **2.71:1**，低于 WCAG 的 4.5:1 | 改 `--ink-muted` (#596761)，实测 **5.94:1**。降权不等于隐身 |
| 顶栏搜索、通知、AI 助手三个控件都挂着"即将开放"（`DisabledControl` 在 shell 里出现 7 次），占据每一屏最显眼的横条 | **撤掉**。空占位比没有更伤信任，而且它们让顶栏看起来是满的，实际什么都做不了 |

**验收**：手算这两处的对比度即可 —— 脚本是阶段 1 的产物，这里还没有。

## 阶段 1 · 无障碍底线，并把它焊进 CI

Apple 把无障碍当约束，不当加分项。现在这个项目没有任何自动检验。

**做什么**

- 写一个 Playwright 脚本，遍历每个路由的每个主要状态，对每个可见文本节点算 WCAG 对比度。**实现要点**：不要从 CSS 反推背景色 —— 半透明叠加、`background-image`、父级混合都会算错。正确做法是截图后按元素 bounding box 采样实际像素，取文字周围的众数作为背景。正文 < 4.5、大字 < 3.0 即失败，输出选择器和实测值。
- 焦点态：每个可聚焦元素必须有可见焦点环，且不被 `overflow: hidden` 裁掉。脚本逐个 `focus()` 并截图比对。
- 键盘路径：差异行展开、看板横向滚动、头像菜单、所有对话框 —— 全部可用键盘完成，且焦点不逃出对话框。
- 屏幕阅读器：每个图标按钮有可读名字；`aria-live` 只用在真正会变的地方。

**验收**：脚本进 `verify.yml`，红了就不能合。这条一旦立起来，后面每个阶段都自动受它保护。

---

## 阶段 2 · 六种状态，每个界面都要有答案

**这是最大的一块，也是最像大厂的一块。** 现在只有"账户已经装满"这一种情况被设计过，而新用户看到的恰恰是相反的那一端。

**先建一个看得见的东西**：`/dev/states` 路由（仅开发环境），把每个组件的六种状态并排渲染在一页上。没有这个页面，"设计每个状态"永远停留在口号。

**已经知道要处理的**

| 界面 | 现在 | 要做 |
|---|---|---|
| 看板 | 一条记录时是 7 列 90% 空白 | **表格为默认**，看板是用户主动选择并被记住的偏好。不设"少于 N 条"的阈值 —— 阈值会让视图在用户没操作时自己跳变 |
| 筛选栏 | 一条记录也渲染完整的两输入框 + 两按钮 | 无可筛内容时折叠成一行文字 |
| 侧栏 | 中间 350px 空白 | 要么放东西，要么收紧 |
| 差异分析 | 只见过 5 条的样子 | 0 条（完全匹配）、20+ 条、单条 JD 原文 500 字 |
| 申请详情 | 公司名短 | 80 字符公司名、无地点、无 JD |
| 职业档案 | 空态刚改过 | 一条、100 条、某分类 50 条 |

**长内容是重灾区**：差异行的英文原文现在占 3 行，压过上面的中文判断。需要 2 行截断 + 展开面板给全文。

**验收**：`/dev/states` 上每个组件的六格都有内容，没有一格写着"没想过"。对每一格截图，人工过一遍。

## 阶段 3 · 把排版变成系统

现在全站有 **31 处**任意值字号（`text-[26px]`、`text-[13.5px]`、`text-[23px]`…），**其中 17 处是我这两个 commit 加的** —— 一边喊系统化一边往里塞新数字。

**做什么**

- 定 7 级 type scale 成 CSS 变量（display / title / heading / body-lg / body / caption / micro），字号、字重、行高、字距一起定死。
- 全站只用这套。`grep -oE 'text-\[[0-9.]+px\]'` 应该返回空。
- 行长约束：中文正文 ~40 字，英文 ~70 字符。每个文本块有 `max-w`。
- 中英混排规则：英文原文用什么字重、什么颜色、是否斜体 —— 现在是每处各写一遍。

**验收**：脚本 grep 不到任意值字号；每个正文块有行长约束。

## 阶段 4 · 暗色模式

不是反色，是重新定义 token 的**角色**。现在的 token 是具体颜色名（`--mint`、`--cream`），不是语义（`--surface-raised`、`--text-secondary`）。

**做什么**

- 先做语义层：`--surface` / `--surface-raised` / `--text-primary` / `--text-secondary` / `--border` / `--accent` / `--danger` / `--success`，具体颜色只在这一层出现一次。
- 暗色下重新定档，不是取反 —— 暗色里 `--cream` 那种高亮度黄会刺眼，要换成低饱和的琥珀。
- 硬投影在暗色下不成立（黑影投在黑底上），要换成边框或内发光。

**验收**：阶段 1 的对比度脚本在暗色下同样通过。这是唯一能证明暗色不是"看起来还行"的办法。

---

## 阶段 5 · 动效规范与零跳动

现在只有我加的那几处，没有规范。

**做什么**

- 分类定义：进入（新内容出现）、退出、位移、状态变化，各自的时长与缓动。现在只有一条 `--ease-out`，不够。
- **消除布局跳动**：RSC 流式渲染会让内容分批到达，页面在加载完成后仍在移动。需要为每个异步区块保留空间。
- 动效必须能回答"从哪来"：差异行展开是从自己的边缘长出来的（已做），但页面切换、卡片删除、列表重排都还是瞬变。

**验收**：Lighthouse CLS = 0；`prefers-reduced-motion` 下截图与静止态一致。

---

## 阶段 6 · 移动端重做

390px 下导航是 6 个换行的药丸，内容开始前吃掉 100px。

**做什么**

- 底部标签栏（4 项）+ 更多抽屉，而不是把桌面导航塞进顶部。
- 差异行在 390px 的可读性：徽章、chip、中英两行、chevron 挤在一起。
- 触控目标 ≥ 44px，间距 ≥ 8px。

**验收**：390 / 768 / 1440 三个断点每页截图人工过；触控目标脚本检验。

---

## 阶段 7 · 文案

**能自动检验的部分**

- 占位不当内容：`未说明` / `暂无` / `N/A` 这类字符串不该出现在渲染结果里 —— 没有值就不渲染这一段。写成 e2e 断言。
- 每条 `errorCopy` 都必须包含一个动作（重试、重新上传、去设置…）。现在 `analysis-control.tsx:73` 的「分析没有完成，请重新尝试。」只说了状态和"再试一次"，没说为什么失败、试之前要不要改什么。可以用一张 `errorCode → 动作` 的表把它变成结构化断言。

**只能人工过的部分**

空状态该说下一步而不是说状态、语气是否一致、中英混排的标点 —— 列一张清单逐条签字。这一阶段没有完整的自动检验，要诚实承认。

## 阶段 附 · 性能也是设计

Apple 那一档里，"感觉快"和"看起来对"是同一件事。这几项不属于任何视觉阶段，但会直接毁掉观感：

- **OCR 负载 32MB**（`public/ocr`，两个 PaddleOCR tiny 模型 + ORT wasm）。首次使用扫描版 PDF 的用户要等这个下载完。之前已经从 56MB 压到 32MB，还有空间。
- **预算**：LCP < 2.0s、CLS = 0、TBT < 200ms，在 4× CPU 降速 + Fast 3G 下测。
- **差异分析 32–49 秒**，而 fetch 超时是 50 秒 —— 这个余量太薄，一次网络抖动就是失败。属于功能问题，但用户体验到的是"这个产品不可靠"。

**验收**：Lighthouse 在 CI 里跑，预算写死，超了就红。

已有 `docs/superpowers/specs/2026-08-30-english-default-and-interaction-polish-design.md`（307 行）和配套 785 行计划，但都写在这轮改版之前，需要先对齐。

## 不做的事

- **不换品牌色板。** 薄荷、珊瑚、奶油、暖白是这个产品的身份，改的是使用纪律。
- **不追求视觉上的"惊艳"。** 这是一个求职工作台，用户在焦虑状态下使用。可靠比惊艳重要。
- **不做动效炫技。** 每一段动画要能说出它解释了什么。

## 顺序与依赖

```
0 (修回归) → 1 (无障碍 CI)  ← 这条立起来后保护所有后续阶段
                ↓
        2 (状态矩阵) ── 最大的一块，也是最值钱的
                ↓
        3 (排版系统) → 4 (暗色) → 5 (动效)
                ↓
        6 (移动端) → 7 (文案) → 8 (英文版)
```

**1 必须最先做**，因为它是唯一能防止后续阶段引入回归的东西 —— 这轮改版我自己就引入了一个对比度失败，没有脚本就发现不了。

**2 是分水岭。** 做完之前，这个产品对新用户是塌的；做完之后，才谈得上其他。

## 规模感

不是承诺，是量级 —— 用来排优先级，不是用来签合同。

| 阶段 | 量级 | 说明 |
|---|---|---|
| 0 清场 | 半天 | 三处，都很局部 |
| 1 无障碍 CI | 2–3 天 | 脚本本身一天，修出来的一堆问题占大头 |
| 2 状态矩阵 | **1–2 周** | 最大的一块。`/dev/states` 一天，剩下是逐个界面做决定 |
| 3 排版系统 | 2–3 天 | 定义半天，替换 31 处 + 回归 |
| 4 暗色 | 3–5 天 | 语义 token 层是主要工作，暗色本身反而快 |
| 5 动效 + 零跳动 | 2–3 天 | CLS 归零可能比动效规范更花时间 |
| 6 移动端 | 4–5 天 | 导航是重做，不是调整 |
| 7 文案 | 2 天 | 人工过为主 |
| 附 性能 | 2–3 天 | OCR 负载是硬骨头 |
| 8 英文版 | 已有 785 行计划，需先对齐 | |

**总计约 5–7 周**，一个人全职。如果只能做一件，做阶段 2。
