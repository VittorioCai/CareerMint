# 海外求职助手：完整 MVP UI 与 AI 助手设计

- 日期：2026-08-14
- 状态：产品方案已由用户确认，等待书面规格复核
- 关联总设计：`docs/superpowers/specs/2026-08-13-overseas-job-search-assistant-design.md`
- 产品形态：桌面优先、兼容手机的响应式 Web App
- 首发用户：申请英语国家岗位的中文求职者

## 1. 本规格的目的与边界

本规格补充总设计中的完整 MVP 界面、账户流程、AI 助手交互和默认模型选择。它覆盖完整产品体验，但不改变“按阶段分别实施”的交付方式。

产品的核心数据链路保持不变：

```text
账户
  -> 职业档案
  -> JD 分析
  -> 定制简历
  -> 投递记录
  -> 面试准备
  -> 申请结果与统计
```

本规格确定以下设计决策：

1. 采用对象中心的信息架构，以结构化工作流为主。
2. 首次使用采用引导流程，日常使用采用高效率工作台。
3. AI 助手位于右侧抽屉，通过文本、结构化上下文和 Tool Calling 工作。
4. AI 助手第一版不接收图片、音频或视频，不需要多模态 API。
5. 默认文本模型为 `deepseek-v4-flash`，通过供应商隔离层调用。
6. 每项 AI 修改都先形成建议或预览，用户确认后才写入业务数据。

## 2. 设计原则

### 2.1 事实优先

- 职业档案中的已确认事实是生成内容的可信来源。
- 待确认或信息不足的事实只能用于提问，不能用于确定性陈述。
- 数字、日期、公司、职位、技能和证书必须能够追溯到具体事实。
- AI 不能静默修改职业档案、投递状态或历史版本。

### 2.2 任务优先

- 每个页面都必须有一个清楚的主要任务。
- 新用户看到下一步引导；熟练用户看到高密度数据和快捷操作。
- 长流程自动保存草稿，并允许用户离开后继续。
- AI 解释不能遮挡主流程，也不能成为完成任务的唯一入口。

### 2.3 状态透明

- 页面明确区分原始数据、AI 草稿、用户编辑和已确认结果。
- 长任务显示排队、处理中、成功或失败状态。
- 保存、同步、导出和删除均提供明确反馈。
- 不只用颜色表示匹配、事实或任务状态。

## 3. 全局信息架构

主导航固定为：

- 首页
- 我的投递
- 职业档案
- 面试题库

全局能力：

- `＋ 新建申请`：始终可见的主操作。
- 全局搜索：搜索公司、职位、投递、职业事实和面试问题。
- 通知中心：显示待跟进申请、临近面试、待确认事实和后台任务结果。
- AI 助手：打开右侧抽屉。
- 账户菜单：个人信息、安全、数据与隐私、退出登录。

统计不占用单独的一级导航。基础统计位于首页，完整统计位于“我的投递”的统计视图。

## 5. 账户与新用户流程

### 5.1 注册与登录

首发版本支持：

- 邮箱与密码注册。
- 邮箱验证。
- 登录与退出登录。
- 忘记密码与重设密码。
- 登录过期后返回原任务的安全重定向。

首发版本不加入 Google、Apple、LinkedIn 或企业单点登录。

### 5.2 账户资料与职业档案分离

账户资料包含：

- 登录邮箱。
- 显示姓名。
- 界面语言。
- 时区。
- 密码与安全设置。
- AI 数据处理偏好。

职业档案包含：

- 工作、项目和教育经历。
- 技能、证书和语言。
- 量化成果。
- STAR 故事。
- 事实状态与来源。

修改账户邮箱、密码或界面偏好不能改变职业事实。

### 5.3 新用户引导

```text
注册账户
  -> 验证邮箱
  -> 填写姓名、目标岗位、目标国家和求职语言
  -> 上传现有简历或跳过
  -> 提取职业事实
  -> 核对重要事实
  -> 进入首页
```

除账户与邮箱验证外，其余引导步骤均可跳过。跳过不会阻止进入产品，但首页会继续显示未完成任务。

## 6. 首页

### 6.1 新用户首页

- 欢迎信息。
- 档案完成度。
- 建档步骤与完成状态。
- `上传第一份简历` 主操作。
- 待确认事实数量。
- 简短的数据与 AI 使用说明。

### 6.2 日常首页

- 本周投递、回复、面试和 Offer 数量。
- 投递漏斗。
- 需要跟进的申请。
- 即将进行的面试。
- 最近申请。
- 待确认或需要补充的职业事实。
- 快速操作：新建申请、记录已有投递、补充职业事实。

每条待办必须直接连接到完成任务的位置，例如 `更新申请状态`、`准备面试`、`继续修改简历` 或 `确认职业事实`。

## 7. 新建申请与 JD 分析

新建申请采用五步引导流程。

### 7.1 添加岗位

- 粘贴完整英文 JD。
- 手动填写公司、职位、地点、岗位链接和来源。
- 在用户输入后自动保存申请草稿。
- 首发版本不自动抓取招聘网站内容。

### 7.2 解析 JD

系统提取并展示：

- 公司、职位、地点和办公方式。
- 核心职责。
- 硬性要求。
- 加分项。
- 技术、工具、语言和行业关键词。
- 签证或工作许可要求。
- 原文明确出现的薪资信息。

用户可以编辑解析结果。公司和职位必须经用户确认后才能建立正式申请工作区。

### 7.3 匹配职业档案

每项岗位要求只能处于以下状态之一：

- `有证据`：存在直接支持的已确认事实。
- `部分匹配`：经历相关，但证据或细节不足。
- `没有证据`：不能在简历中确定性陈述。
- `需要判断`：系统无法可靠判断，需要用户选择。

展开一项要求时显示对应事实、原始来源、匹配理由、补充问题和是否纳入本次简历。

### 7.4 补充资料

系统集中提出少量高价值问题，例如项目规模、结果数字或技能使用场景。每个答案可选择：

- 仅用于本次申请。
- 保存为待确认事实。
- 用户确认后加入职业档案。

### 7.5 建立申请工作区

保存 JD 原文快照、结构化要求、匹配结果、相关事实和申请草稿。重新解析同一草稿时更新解析结果，不重复创建申请。

## 8. 定制简历编辑器

桌面端采用三栏布局：

- 左栏：简历结构、排序、显示状态和部分相关度。
- 中栏：接近最终文档的正文预览与行内编辑。
- 右栏：AI 建议、JD 理由和事实证据。

每条 AI 建议显示：

- 原文。
- 建议文本。
- 修改理由。
- 对应 JD 要求。
- 引用的职业事实。
- `接受`、`编辑后接受`、`拒绝` 操作。

编辑规则：

- 纯措辞优化可以直接接受。
- 新增或改变事实必须关联已有事实，或由用户确认后新增事实。
- 无来源的数字、日期、公司、职位、技能或证书显示阻断性风险。
- 存在阻断性事实风险时不能导出。
- 支持撤销、重做、自动保存和未同步提示。

版本规则：

- 首次生成形成 V1。
- 重要修改可以保存为新版本。
- 支持版本比较和恢复。
- 正式投递后的最终版本成为不可变历史快照。

导出支持 DOCX 和 PDF，以及“简洁”“现代”两种固定模板。导出完成后显示 `记录本次投递`，由用户确认日期、渠道和初始状态。

## 9. 我的投递

### 9.1 看板视图

```text
准备中 -> 已投递 -> HR 沟通 -> 面试 -> Offer
                              \-> 已拒绝
                              \-> 已撤回
```

支持拖动更新阶段。移动后必须确认实际发生日期，并生成阶段事件。

### 9.2 表格视图

显示公司、职位、地点、阶段、投递日期、渠道、简历版本、下一步行动和最后更新时间。

支持按公司、职位类型、地点、日期、阶段、渠道和是否需要跟进筛选。

### 9.3 统计视图

显示投递总数、回复率、面试率、Offer 率、阶段平均耗时、渠道表现、岗位分布、地点分布和时间趋势。

统计只描述记录中的结果和相关性，不宣称某个简历版本或渠道导致结果变化。

## 10. 投递详情

顶部固定显示公司、职位、阶段、地点、来源和下一步行动。

详情页包含五个标签：

1. **概览**：当前阶段、关键日期、匹配摘要、下一步行动和联系人。
2. **JD**：原始快照、结构化要求、事实匹配和能力缺口。
3. **简历**：生成历史、最终投递版本、下载、对比和事实来源。
4. **面试准备**：题目、回答提纲、准备状态和笔记。
5. **时间线**：创建、修改、投递、状态变化、沟通、面试和反馈记录。

## 11. 职业档案

职业档案按以下类别分组：

- 基本信息。
- 工作经历。
- 项目经历。
- 教育背景。
- 技能。
- 证书。
- 语言。
- 量化成果。
- STAR 故事。

每条事实显示内容、来源、更新时间、确认状态，以及被哪些申请和简历版本引用。

用户可以新增、编辑、确认、标记需要补充、删除或合并重复事实。编辑已确认事实后，该事实重新进入待确认状态。

删除已被历史版本使用的事实时显示影响提示。未来生成不再使用该事实，但历史投递版本仍保留当时快照。

## 12. 面试题库与岗位准备

题目分为通用题、职能题、行业题和岗位特定题。

同一个核心问题只保存一次，不同问法作为变体保存。不同岗位通过关联记录复用题目，并分别保存优先级、准备状态、回答提纲和笔记。

准备状态为：

```text
未开始 -> 已列提纲 -> 已练习 -> 已准备
```

AI 可以：

- 根据 JD 生成可能的岗位问题。
- 检查共享题库中是否已有相似问题。
- 为岗位组合通用题、职能题和新增岗位题。
- 从已确认事实和 STAR 故事中选择证据。
- 生成要点式回答提纲并指出证据缺口。

AI 不能声称知道雇主一定会问什么，也不能创造用户没有的故事。

## 13. AI 助手

### 13.1 交互形态

AI 助手是可展开的右侧抽屉，而不是产品主导航或独立聊天首页。抽屉包含：

- 当前上下文说明，例如“正在查看：Acme / Product Manager”。
- 对话记录。
- 当前会话标题与 `新建会话` 操作。
- 建议快捷问题。
- 文本输入框。
- AI 提议的预览卡片。
- 来源和相关页面跳转。

首发版本只支持文本输入，不显示图片、语音或视频附件按钮。PDF 和 DOCX 由文件处理模块提取文本，不作为多模态消息交给助手。

### 13.2 页面上下文

应用直接向助手提供最小必要的结构化上下文，不通过截图让模型识别页面。上下文可以包含：

- 当前页面类型和对象 ID。
- 当前申请的基本信息。
- 已确认的 JD 要求。
- 与当前任务相关的职业事实 ID。
- 当前简历版本或面试题 ID。
- 用户主动选择的文本。

默认不发送账户密码、安全设置、其他无关申请或全部历史数据。

### 13.3 会话与记忆

- 会话按全局、申请、简历版本或面试准备对象分线程保存，不建立一个可以隐式访问全部数据的全局长对话。
- 用户可以查看同一对象的近期会话、新建会话、修改标题或删除会话。
- 跨页面跳转后，只有用户明确选择的会话继续携带上下文。
- 每次请求只发送稳定系统提示、当前结构化上下文、该会话的滚动摘要和最近 12 条用户/助手消息。
- 滚动摘要只用于保持对话连续性，不能成为新的职业事实或事实来源。
- 删除申请时同时删除其助手会话；账户导出和账户删除必须包含全部助手会话数据。

### 13.4 允许的工具

助手通过业务级工具工作，不获得通用数据库访问能力。首发工具包括：

- `get_current_application`：读取当前申请摘要。
- `search_confirmed_career_facts`：搜索已确认职业事实。
- `explain_requirement_match`：解释某项匹配结果。
- `draft_resume_suggestion`：生成带证据的简历建议草稿。
- `draft_interview_questions`：生成并去重岗位问题候选。
- `draft_answer_outline`：生成带事实引用的回答提纲。
- `suggest_next_action`：依据现有记录提出下一步建议。

工具必须验证登录用户和资源所有权。读取工具只返回完成当前请求所需的字段。

### 13.5 写操作确认

助手不能直接确认事实、改变投递阶段、覆盖简历、删除数据或创建正式投递记录。

需要写入时按以下流程处理：

```text
用户提出请求
  -> 助手调用只读工具并形成变更建议
  -> 页面展示字段级预览
  -> 用户点击确认
  -> 应用执行受权限控制的业务操作
  -> 页面反馈结果
```

用户拒绝或关闭预览时不产生业务数据变更。

## 14. DeepSeek 模型与供应商边界

### 14.1 默认模型

默认模型标识为 `deepseek-v4-flash`，通过 `https://api.deepseek.com` 的 OpenAI 兼容 Chat Completions 接口调用。

DeepSeek 官方资料显示该模型支持 JSON Output 和 Tool Calls，但模型本身是纯文本模型：

- [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing)
- [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)
- [DeepSeek V4 text-only note](https://api-docs.deepseek.com/quick_start/agent_integrations/github_copilot/)

### 14.2 供应商隔离

业务模块依赖 `AIProvider` 接口，而不是 DeepSeek SDK 或具体模型名。接口至少包含：

- 结构化文本提取。
- 结构化候选生成。
- 带工具的助手对话。
- 用量与完成状态返回。

DeepSeek 适配器负责请求格式、JSON 解析、Tool Call 映射、错误转换和 token 用量读取。更换模型时不改变职业事实、JD、简历或面试模块。

### 14.3 输出验证

- 请求使用 JSON Output 时，提示词明确要求 JSON 并提供完整结构示例。
- 返回内容先解析为 JSON，再通过 Zod 业务结构校验。
- `finish_reason` 表示截断、返回空内容或结构不合法时，任务失败并允许幂等重试。
- Tool Call 参数必须经过逐工具 Zod 校验。
- 模型返回的资源 ID 不能作为授权依据，服务端必须重新验证所有权。
- 模型输出仍须经过事实证据规则，合法 JSON 不等于真实事实。

### 14.4 成本控制

- 简单提取、匹配和助手请求默认关闭 thinking mode。
- 不在用户每次按键时调用模型，只在明确的分析、生成或发送操作后调用。
- 文件解析、文本规范化、确定性去重和事实验证在本地程序中完成。
- 相同输入与任务版本复用幂等结果。
- 固定提示与 JSON 示例位于稳定前缀，便于命中供应商缓存。
- 每项任务限制输入长度、输出 token 和重试次数。
- 助手单次回复最多生成 1,200 个输出 token；结构化提取任务最多生成 4,096 个输出 token。
- JSON 为空、截断或校验失败时最多自动重试一次，第二次失败后交给用户手动重试。
- 同一用户最多同时运行两个 AI 任务；超出时任务排队而不是并行重复请求。
- 服务端按用户统计每日输入、缓存命中和输出 token，并设置部署级每日预算上限；达到上限后保留草稿并显示何时可重试。
- 只记录 token 数、模型、延迟、状态和估算成本，不记录简历或 JD 正文。
- 自动化测试使用固定模拟结果，不访问真实 DeepSeek API。

## 15. 搜索、通知与异常恢复

### 15.1 搜索

全局搜索覆盖公司、职位、投递记录、职业事实和面试问题。搜索结果按类型分组，并跳转到具体对象。

### 15.2 通知

通知包括：

- 申请需要跟进。
- 面试临近。
- 职业事实待确认。
- AI 分析成功或失败。
- 文档导出完成。

### 15.3 异常恢复

- 简历无法解析：保留原文件，允许粘贴文字或手动建档。
- JD 解析失败：保留原文与手工字段，允许重试。
- AI 请求失败：保留当前草稿，不丢失用户编辑。
- 网络断开：显示未同步状态并允许安全重试。
- 没有事实证据：转换为补充问题，不生成虚假描述。
- 重复请求：复用同一幂等任务，避免重复写入和重复计费。
- 导出失败：保留已确认内容和版本，允许重新导出。

## 16. 响应式和可访问性

桌面端优先支持建档、JD 分析、三栏简历编辑、看板和统计。

手机端优先支持查看待办、更新申请阶段、阅读面试题、编辑笔记以及查看联系人和面试安排。

移动端简历编辑器将三栏改为顺序标签：

```text
正文 -> 建议 -> 证据
```

界面要求：

- 所有核心操作支持键盘。
- 状态同时使用文字、图标和颜色。
- 表单错误靠近具体字段显示。
- 删除、导出、事实确认和阶段变化提供明确结果。
- 长任务显示进度，允许用户离开页面后继续。
- 空状态说明原因并提供下一步操作。

## 17. 隐私与账户管理

账户设置通过头像菜单进入，不占用一级导航。

账户设置包含：

- 个人信息：姓名、界面语言和时区。
- 登录与安全：邮箱、密码与当前会话。
- AI 与数据：说明哪些内容会发送给外部模型服务。
- 数据导出：导出职业档案、申请记录、题库个人数据和文件。
- 删除账户：二次确认后删除个人文件和派生数据。

AI 输入必须按当前任务最小化。应用日志不保存简历、JD、回答提纲或对话中的个人正文。首发版本不使用用户资料训练公共模型。

## 18. 测试与验收

### 18.1 界面测试

- 新用户可以完成注册、邮箱验证和可跳过的建档流程。
- 首页根据用户状态展示正确的下一步操作。
- 新建申请流程在刷新或离开后保留草稿。
- 看板阶段变化生成准确的阶段事件。
- 简历建议必须显示 JD 理由和事实来源。
- 通用面试题可被多个岗位复用，不重复创建正文。

### 18.2 AI 助手测试

- 助手只能获得当前任务所需的结构化上下文。
- 助手不能通过工具读取其他用户数据。
- 所有工具参数经过结构验证。
- 写操作必须先显示预览，未确认时数据库不变化。
- 恶意简历、JD 或聊天内容不能扩大工具权限。
- 空 JSON、截断 JSON、非法 Tool Call 和供应商错误均转换为可恢复状态。
- 测试环境不会调用真实 DeepSeek API。

### 18.3 产品验收路径

```text
新用户注册并建档
  -> 上传简历并确认事实
  -> 粘贴 JD 并确认岗位要求
  -> 查看证据匹配
  -> 审核并导出定制简历
  -> 记录投递并更新阶段
  -> 准备通用题和岗位题
  -> 查看申请统计
  -> 导出或删除个人数据
```

该路径中的每个 AI 结果都必须可追溯、可拒绝、可重试，并且不能绕过用户确认。

## 19. MVP 非目标

- 图片、语音或视频形式的 AI 助手输入。
- 语音模拟面试和语音评分。
- 招聘网站自动抓取。
- 自动投递。
- 邮箱、日历、LinkedIn 或云盘同步。
- 浏览器扩展。
- 企业团队账户和管理后台。
- 无需事实来源的自由简历生成。
- AI 自动确认事实、发送申请或删除用户数据。

## 20. 分阶段实施关系

本规格描述完整 MVP，但仍按以下独立闭环实施：

1. 账户、职业档案、文件上传与事实确认。
2. JD 解析、事实匹配、简历编辑与导出。
3. 投递看板、详情、时间线与统计。
4. 共享题库、岗位题单与回答提纲。
5. AI 助手及跨页面 Tool Calling。

现有首阶段实施计划需要在本规格通过用户书面复核后更新：移除旧供应商专用适配器，改为供应商隔离层和 DeepSeek Chat Completions 适配器，同时保持阶段 1 的数据与事实安全边界不变。首发实现只接入 DeepSeek，不同时维护第二个线上模型供应商。
