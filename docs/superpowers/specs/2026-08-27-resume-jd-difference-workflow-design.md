# 岗位与简历差异工作流设计规格

**日期：** 2026-08-27  
**状态：** 用户已确认设计，可进入实施
**建议版本标识：** `resume-jd-difference-v4`  
**产品范围：** 申请详情中的“简历 → 差异分析 → 完善建议 → 面试准备”工作流

## 1. 背景与问题

当前 `JD 差距分析 V3` 更接近资格与证据审核：它把 JD 拆成条件，再判断简历是否提供严格证据。该方法适合识别语言、学历、工作许可和证书等门槛，但没有准确解决本产品在这一阶段最重要的问题：

> 用户已经为当前岗位选择一份简历后，系统应帮助用户发现这份简历与 JD 的表达差异，指出哪些岗位重点没有覆盖、没有说清或没有使用招聘方熟悉的岗位语言。

有效的关键词调整不是把 JD 原词复制进简历，而是把用户真实做过的事情，用目标岗位能够识别的语言重新表达。不同公司可能使用 `dashboard`、`reporting` 或 `visualization` 描述相近工作；也可能使用 `requirements gathering`、`business analysis` 或 `translate business needs into technical requirements` 描述相近职责。系统需要识别这种语义对应，同时防止把相邻表达错误升级为不存在的工具、方法、职责或成果。

现有页面还容易把旧结果、处理中状态和新分析入口同时展示，令用户无法判断当前看到的是哪一次分析。新版必须建立清晰的顺序、状态和版本边界。

## 2. 产品目标

- 以当前申请中用户已经选择的简历为唯一对照简历。
- 先判断 JD 真正重视的岗位目标、核心能力和岗位语言，再分析简历差异。
- 区分字面匹配、语义对齐、表达过弱、位置不当、证据缺失和岗位门槛。
- 让用户知道“岗位要求什么、简历现在表达了什么、问题在哪里、为什么重要”。
- 保留全部问题，同时用总体判断和优先级帮助用户先处理高价值问题。
- 在独立的“完善建议”板块给出调整方向，但不生成替换句子、不自动修改简历。
- 所有建议必须绑定当前简历或已确认职业事实，不得虚构经历。
- 一次用户触发的分析同时产出“差异分析”和“完善建议”所需数据，不再为完善建议单独调用模型。
- 保持结果可缓存、可追踪、可解释，并在输入变化后可靠地标记过期。

## 3. 明确排除

- 不生成可直接粘贴的改写句子。
- 不提供接受、拒绝或自动替换简历内容的操作。
- 不自动修改简历、职业档案或任何历史投递快照。
- 不按照当前 JD 自动选择、推荐、复制或建立基础简历版本。
- 不显示匹配百分比、录取概率或候选人综合胜任分数。
- 不把“当前材料没有证据”表述成“用户不具备该能力”。
- 不把所有 JD 名词都当成关键词，也不鼓励在技能区堆砌关键词。
- 不在普通日志中保存完整 JD、简历或模型原始回答。

## 4. 核心工作流

申请详情导航顺序调整为：

`概览 → 简历 → 差异分析 → 完善建议 → 面试准备 → 时间线`

这是软性工作流：有顺序、有状态、有下一步引导，但不锁死后续页面。

1. **简历**：用户上传或选择本次申请的简历，并通过预览确认版本。
2. **差异分析**：用户主动点击“开始差异分析”。系统读取 JD、所选简历和已确认职业事实，生成本次分析。
3. **完善建议**：读取同一次分析结果，展示与具体问题对应的完善方向。
4. **面试准备**：用户可以继续准备面试；不要求先完成或勾选全部完善建议。

软性约束：

- 未选择简历时，“差异分析”页面仍可打开，但只显示选择简历的引导和跳转按钮。
- 差异分析未完成时，“完善建议”页面仍可打开，但只显示“请先完成差异分析”。
- 分析完成后显示“下一步：查看完善建议”，但不自动跳转。
- 用户可以跳过完善建议，直接打开面试准备。
- 用户随时可以返回前一步，不丢失当前结果。

## 5. 分析输入与单次输出

### 5.1 输入

一次分析只读取：

- 当前申请保存的 JD 快照；
- 当前申请选择的简历资源及其解析文本；
- 当前用户已经确认、带来源的职业档案事实。

未确认职业事实不得作为证据。其他申请的简历不得参与当前结果。

### 5.2 单次结构化输出

一次模型调用返回一份严格 JSON 结果，包含以下三组数据。

#### A. 岗位核心判断

- 岗位的主要目标；
- 3–5 项核心能力；
- 高频且与核心任务直接相关的岗位概念；
- 每个概念在 JD 中出现的原词或短语；
- 概念的重要性依据；
- 明确必需门槛；
- 加分项。

岗位概念可以聚合同义或相邻表达，但必须保留 JD 的实际原词。例如 `dashboard`、`reporting` 和 `visualization` 可以被归入“报告与可视化”概念，但不能抹掉三者的语义差别。

#### B. 简历差异

每个具体问题至少包含：

- 稳定问题 ID；
- 关联的岗位概念；
- JD 原文；
- 中文解释；
- 当前简历引用或 `null`；
- 相关已确认职业事实 ID；
- 问题类型；
- 判断依据；
- 优先级；
- 是否属于无法通过调整措辞解决的岗位门槛。

#### C. 完善方向

每条完善方向必须关联一个具体问题 ID，并包含：

- 建议完善的简历区域或具体经历；
- 建议对齐的 JD 岗位概念和原词；
- 建议加强的重点：动作、业务场景、协作对象、方法或结果；
- 可以参考的同义岗位语言；
- 真实性状态；
- 是否需要用户先确认事实；
- 简短的方向说明。

完善方向不得包含完整替换句或可直接粘贴的改写文本。

## 6. 岗位核心判断方法

系统不使用单纯词频决定重点。程序先进行无语义扩张的基础预处理，例如分段、重复短语统计和职责/要求位置标记；模型再综合判断岗位概念的重要性。

核心信号包括：

1. 是否同时出现在职责和要求中；
2. 是否在 JD 中反复出现；
3. 是否直接关联岗位主要任务；
4. 是否属于明确必需条件；
5. 是否只是公司介绍、福利、口号或泛化软技能。

整体判断必须先回答“这个岗位主要希望候选人解决什么问题”，再列出核心能力和岗位语言。不能只返回关键词清单。

## 7. 简历差异分类

### 7.1 完全缺失

当前简历和已确认职业事实均没有相关证据。统一措辞：

> 当前材料未找到相关证据。

系统不得据此断定用户本人不会，只能提示“如果确实做过，请补充真实经历；如果没有，不要加入简历”。

### 7.2 岗位语言未对齐

简历存在真实、可回查的相近经历，但使用了招聘方不常用或不同的表达。系统说明语义对应依据，并在完善建议中列出可参考的 JD 语言。

只出现相同主题、职位名称或行业背景不能算语义对齐。

### 7.3 职业档案有但简历未体现

已确认职业档案中存在相关事实，但当前对照简历没有表达。差异分析明确区分“用户已有可核实事实”和“本次简历尚未体现”，完善建议可以指向该事实及其来源，但不能静默写入简历。

### 7.4 只在技能区出现

简历列出了工具或能力，但工作或项目经历中没有使用场景。问题说明应强调缺少行为证据，而不是建议重复堆词。

### 7.5 描述过于笼统

简历存在相关动作，但无法判断具体职责、对象或工作内容。例如只写“负责报表”而没有说明数据、受众或用途。

### 7.6 缺少场景或对象

简历没有说明为谁工作、解决什么业务问题、与谁协作或在哪种系统环境中使用相关能力。

### 7.7 缺少结果

简历只描述任务，没有呈现结果、影响、交付物或可核实成果。只有 JD 或岗位核心明确重视成果时，才把它提升为高优先级问题；系统不得要求用户编造数字。

### 7.8 需要本人确认

简历和职业档案存在相邻信息，但不足以确定用户是否真实做过。完善方向必须先要求用户确认，不能直接建议使用该岗位语言。

### 7.9 岗位门槛问题

工作许可、明确语言级别、学历层级、最低年限、证书和执照等无法通过措辞调整解决，单独进入“岗位门槛待确认”区域。

## 8. 同义词与真实性规则

同义对齐的目的，是用目标岗位熟悉的语言描述用户已经做过的事情，不是扩张经历。

允许语义判断的内容：

- 职责、业务动作和协作方式；
- 相同业务目的下的常见行业表达；
- 能由简历原文或已确认事实明确支持的语言重心调整。

必须严格判断的内容：

- 具体工具、框架、云平台和技术方法；
- 年限、数量、规模和任何数字；
- 语言等级；
- 学历层级；
- 证书、执照和工作许可；
- 管理职责、决策权限和业务结果。

真实性状态分为：

- `supported`：当前简历有直接或语义等价证据，可以安全提出表达方向；
- `profile_only`：已确认职业档案有证据，但当前简历没有体现；
- `needs_confirmation`：只有相邻线索，需要用户先确认；
- `unsupported`：当前材料没有证据，不得建议加入。

职业档案证据不能把“当前简历未体现”升级成“简历已经覆盖”。

## 9. 优先级与排序

优先级综合以下因素判断：

`明确岗位门槛 → 核心任务且多次强调 → 重要职责或能力 → 加分项`

“岗位门槛”与“简历表达问题”是两个独立区域，避免误导用户认为修改措辞可以解决真实资格问题。

差异分析顶部只突出三个最重要的问题。下方“具体差异”保留全部问题，不限制数量，按关键、重要、次要排序。每项默认收起为摘要；展开后完整显示内容。已经充分表达的内容放在底部整体折叠区，并显示数量。

## 10. 页面设计

### 10.1 标签与命名

- 原 `JD` 标签改为 **差异分析**。
- 页面主标题为 **岗位与简历差异分析**。
- 页面说明为：**找出这份简历尚未覆盖、表达不清或无法证明的岗位重点。**
- 主按钮为 **开始差异分析**；完成后为 **重新分析**。
- 新增独立标签 **完善建议**，位于差异分析之后、面试准备之前。

### 10.2 差异分析页面顺序

1. 本次对照简历：文件名、预览入口和重新选择入口；
2. 岗位核心判断；
3. 这份简历的总体差异；
4. 具体差异；
5. 岗位门槛待确认；
6. 已经对上的内容；
7. 下一步：查看完善建议。

每条具体差异展开后同时显示：

1. JD 原文；
2. 中文解释；
3. 简历现状；
4. 问题点；
5. 判断依据；
6. 优先级；
7. 必要时显示职业档案补充。

JD 原文和中文解释同时展示，不再为原文设置单独折叠层。

### 10.3 完善建议页面

完善建议读取同一分析结果，按以下类别分组：

- 岗位语言未对齐；
- 经历证据需要加强；
- 关键词位置较弱；
- 需要本人确认；
- 不能通过改简历解决。

每条建议显示对应的问题、目标简历位置、岗位语言、调整重点、真实性状态和方向说明。页面不显示直接改写文本，不提供接受或拒绝按钮。

页面末尾提供“下一步：面试准备”。不显示基础版本管理或准备多方向简历的通用提醒。

## 11. 状态、缓存与版本

缓存键至少包含：

- JD 快照哈希；
- 所选简历文件哈希；
- 已确认职业事实指纹；
- Provider 与模型；
- Prompt、Schema 和安全策略版本。

所有字段相同时复用成功结果，不重复调用模型。JD、所选简历、已确认事实或版本变化后，差异分析与完善建议同时标记过期；系统不自动调用 AI。

新分析进行中：

- 主页面只显示当前进度；
- 上一次结果默认隐藏在“查看上次结果”入口中；
- 不把旧版结果放在新分析主流程下方；
- 成功后原子地更新差异分析和完善建议。

分析失败：

- 保存失败状态和稳定错误码；
- 保留上一次成功结果；
- 明确说明旧结果不是当前分析；
- 允许用户重试，不创建重复任务。

旧 `JD 差距分析 V3` 结果保留为历史只读数据，不与新版结果混合。新版使用独立版本和缓存键。

## 12. 确定性校验

模型输出保存前必须通过：

1. JSON Schema 严格键校验；
2. 岗位概念、问题和完善方向 ID 的完整性与唯一性校验；
3. JD 引用在 JD 快照中的回查；
4. 简历引用在所选简历解析文本中的回查；
5. 职业事实 ID 的所有权、存在性和确认状态校验；
6. 具体工具、数字和资格的严格约束检查；
7. 完善方向与具体问题的一对一或多对一关联校验；
8. 直接改写句、完整简历内容和未知事实的拒绝或降级。

引用无效时，系统删除无效引用并把真实性状态降为 `needs_confirmation` 或 `unsupported`，不能保留乐观结论。

## 13. 错误与异常处理

- PDF 或 DOCX 解析失败时保留文件，允许重试、OCR 或更换简历。
- 简历文字不足时提供本地 OCR；不得静默把空文本送给模型。
- 模型超时、限流或格式错误时保留旧结果与用户选择。
- 部分结果不完整时整次结果不发布，避免差异分析和完善建议不一致。
- 网络中断时显示未完成状态，页面刷新后可恢复或重试。
- 结果过期、分析失败和历史结果必须使用不同状态文案。

## 14. Prompt 评测与验收

使用精简、匿名的英语和德语测试案例，并保留中文输出检查。测试集至少覆盖：

- 核心词与普通名词区分；
- 职责与要求中重复概念的优先级；
- 同义职责表达；
- 只有关键词、没有真实场景；
- 有动作但缺少对象、场景或结果；
- 职业档案有证据但简历未体现；
- 当前材料完全没有证据；
- 工具、年限、语言、学历、证书和许可的严格陷阱；
- 防止相邻行业、相邻工具或相似职位名称造成误判。

Prompt 候选以以下硬性指标筛选：

- 核心问题召回率；
- 虚假语义对齐数量；
- 无证据内容误报数量；
- 问题类型准确性；
- 优先级合理性；
- 完善方向与问题关联完整性；
- 直接改写句和虚构事实数量必须为零；
- 输出 Schema 合法率。

前端与端到端验收覆盖：

- 选择简历后开始分析；
- 差异分析与完善建议使用同一运行结果；
- 全部问题可访问，已匹配内容默认折叠；
- 软性工作流允许跳转；
- 更换 JD、简历或确认事实后两页同步过期；
- 分析中不混入旧结果；
- 失败后可查看上次成功结果并重试；
- 桌面与手机端无横向溢出，键盘可操作，状态不只依赖颜色。

## 15. 成本与隐私

- 仅在用户点击“开始差异分析”或“重新分析”后调用模型。
- 同一输入复用结果；重复点击不重复扣费。
- 完善建议不发起第二次模型调用。
- 固定系统提示词前置，JSON 输出限制长度，程序先做文本和引用预处理。
- 记录 Provider、模型、Prompt 版本、Token 和估算成本；不记录原始材料正文。
- CI 和自动化测试使用 mock；真实 Prompt 对比使用小型匿名样本并设置费用上限。

## 16. 完成标准

该工作流完成时，用户能够：

1. 明确知道系统正在比较哪份 JD 和哪份简历；
2. 先理解岗位核心，再理解这份简历的总体问题；
3. 查看所有具体差异，而不是只看到若干模型挑选项；
4. 区分表达问题、证据问题和真实岗位门槛；
5. 在独立页面获得与问题对应的完善方向；
6. 确认系统没有生成替换句、虚构经历或自动修改材料；
7. 自由进入面试准备，不被硬性步骤阻塞；
8. 在材料变化后看到明确的过期状态并主动重新分析。
